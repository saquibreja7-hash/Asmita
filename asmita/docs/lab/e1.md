# E1: detector benchmark and morph-robust matching

Charter: `asmita/docs/lab/charter.md` (experiment E1). Harness: `tools/lab-bench/`
(WP52, branch `feat/lab-bench`). This card holds the method and the aggregate
results table; a real run's numbers are filled in below and nowhere else.
Methodology and aggregate numbers only — no per-image data, no service names.

**Question.** Which "AI-made / manipulated" detectors, and which matching
methods, hold up on Indian faces and WhatsApp-compressed morphs?

**Status.** Harness built and unit/integration-tested (2026-11-20). No real
run has happened yet: the tables below are empty until one does. A real run
needs a local portraits folder (clothed, non-intimate photos of consenting
adults) that is research data on local disk and never committed.

## Method

Test set, built by `tools/lab-bench build-set <portraits-dir> <out-dir>`:

- One untouched original per portrait (the matching gallery, byte-identical).
- Per portrait, deterministic variants: a 90%x90% crop at a fixed offset,
  a 0.6x bicubic resize, a mirror flip, a caption-sticker overlay, a
  screenshot with status-bar and borders, a WhatsApp-style re-encode (long
  edge capped at 1600, JPEG quality 70, 4:2:0), a landmark-aligned face-swap
  composite (eyes aligned exactly by rotation, scale and translation;
  colour-matched patch through a Gaussian-feathered elliptical mask — CPU
  only, OpenCV-free), and that composite put through the WhatsApp re-encode
  (the stop-rule combination). Pixel-only variants re-encode losslessly so
  each row measures its alteration alone.
- Labels: every variant of a real photograph is `real` (an honest detector
  must not flag a cropped or re-shared real photo); the face-swap composites
  are `fake`. A labelled folder from a public deepfake dataset (`real/` +
  `fake/`) can be imported alongside, keeping its labels.

Matching, scored by `tools/lab-bench match <set-dir>`:

- Methods: whole-image PDQ (the production baseline, imported from
  `asmita/src/lib/pdq`, with the crawler's quality floor of 50), SSCD
  (`sscd_disc_mixup` ONNX, loaded as on `origin/feat/crawler-sscd`), PDQ on
  the face crop only, and PDQ on the background with the face masked out.
- Pairs: a probe's genuine pair is the original it was built from; its
  impostor pairs are every other gallery original, plus the gallery-vs-
  gallery pairs as a probe-independent noise floor. Face location for the
  region methods is @vladmandic/human's detector + mesh (WASM, CPU).
- Metric: per transform, the threshold is calibrated on that transform's
  impostor pairs so the false-match rate stays at or below 1%, and recall is
  the share of genuine pairs matched at it. With N portraits a transform has
  N(N-1) probe-impostor pairs plus the gallery floor, so runs should use
  N >= 30. Thresholds and pair counts are recorded in each run directory.

Detection, scored by `tools/lab-bench detect <set-dir>`:

- Adapters behind one interface, each skipped unless its key (or, for the
  local model, its weights) is present: OpenAI vision (`OPENAI_API_KEY`),
  Hive (`HIVE_API_KEY`), Sightengine (`SIGHTENGINE_USER`/`SIGHTENGINE_SECRET`),
  and the local Community Forensics ViT-S/16 384 (MIT; Park & Owens,
  arXiv 2411.04125) through onnxruntime-node. All scores are P(AI-made /
  manipulated) in [0,1].
- Metric: accuracy per transform (the provider's own verdict when it gives
  one, otherwise score >= 0.5) and AUC per transform, computed on the
  transform's items pooled with the untouched originals (blank where a pool
  has a single class — an honest detector's false-flag rate on innocent
  transforms shows up in the accuracy column).
- The hosted adapters' response schemas follow the providers' public API
  docs; the first keyed run must spot-check the recorded raw responses.

Reports: `tools/lab-bench report <run-dir>` writes `report.md` + `report.html`
locally (gitignored). Only the aggregate tables below are published.
