# Flagged links: review guidance

> Draft: not reviewed. Written from the code and existing console docs; it
> carries no legal advice and nothing in it replaces the owner's word.

## What this queue holds

Links a survivor submitted that wait for a human decision before a notice
can be queued. A link lands here when it was flagged at filing time
(too many links at once, many unrelated domains, a high-volume submitter, a
brand-new account, a repeatedly rejected target, the same address targeting
the same person, or a known public or news domain) or when its platform is
unknown, so it needs investigation.

## What the screen shows

The case reference, the platform, the masked domain and the flag reason. The
full address is never shown; revealing one is a separate, reasoned, recorded
action on the case page.

## Deciding

- **Approve link** moves the link to the notice queue. It sends nothing:
  dispatch still needs the survivor's signature, a legally reviewed template
  and a human-verified contact.
- **Reject link** closes the link for the case. On this console the reason
  you pick is internal, encrypted, and never reaches the survivor; her
  record keeps the same empty flag reason as today's one-click buttons. The
  Flagged page keeps its own picker for the reason she will see.
- An **unknown platform** cannot be approved; the existing review refuses it.
  Investigate the platform's public reporting route and reject.

## Good practice

The four-hour review target is counted from submission; the queue list shows
the oldest waiting item so breaches are visible before they happen. When two
links are the same content on the same platform, deciding one and rejecting
the duplicate keeps the case clean. The case timeline below the item shows
what has already happened; previous decisions show as a reviewer handle,
never an email.
