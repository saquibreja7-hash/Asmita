## Verdict

### GO: Node + sharp with pdq.ts for the crawler

Basis: Node-vs-browser distance for the SAME file (node-prepared), not original-vs-transformed distances. Rule: GO if every class that matters (JPEG/PNG/WebP in RGB, greyscale, alpha, palette, EXIF-rotated, all sizes, CMYK) agrees within 10; classes above 10 are listed as exceptions.

- Max **10** (photo-cmyk-icc.jpeg), p99 10, p95 0, mean 0.2; exact matches 71/74. Margin from the worst image to the 31 match threshold: 21 bits. Baseline recipe max: 50.
- Images above 10: none.
- Every image with non-zero distance: photo-cmyk-icc.jpeg (cmyk, 10); photo-cmyk.jpeg (cmyk, 6); photo-alpha.png (alpha, 2).
- Exceptions: none on this synthetic set. Known unsupported or weak spots are in the caveats below.

### Decode settings the crawler must use

Use `prepareForPdq()` from src/prepare.ts verbatim. It is:

```ts
sharp(buffer, { failOn: 'none', limitInputPixels: 25_000_000, animated: false })
  .rotate()                 // apply EXIF orientation (browser: imageOrientation 'from-image' is the default)
  .toColourspace('srgb')    // greyscale / ICC -> sRGB; CMYK WITHOUT a profile is converted naively (1-C)(1-K) like Chromium
  .ensureAlpha()            // RGBA, 4 bytes/pixel like ImageData
  .raw()                    // no .resize(): pass FULL resolution; pdq.ts downsamples itself
// then emulate the canvas premultiply round trip for alpha < 255 (transparent -> 0,0,0)
```

- **Resize:** none. The browser draws 1:1 with smoothing off and pdq.ts does its own 512x512 nearest-neighbour step, so pre-resizing in sharp (any kernel) would diverge from the browser. If memory forces a pre-resize, re-run this harness with that kernel first.
- **Orientation:** `.rotate()` with no arguments. Skipping it breaks every EXIF-rotated JPEG.
- **Colour:** `toColourspace('srgb')`; do not use `.greyscale()` or strip profiles. CMYK without an embedded profile must use the naive conversion (sharp's default lcms CMYK profile disagreed by 44 bits); CMYK with a profile uses the normal path (measured 10, the edge of tolerance, one synthetic profile only).
- **Alpha:** keep alpha, emulate the canvas round trip (see `canvasAlphaRoundTrip`).
- **Animated:** first frame only (`animated: false`).

### Caveats

- Fixtures are synthetic. Real photographs have more high-frequency detail and real JPEG quantisation; agreement on real images should be re-checked with a benign public-domain photo set before launch.
- Text fixtures are blocky pseudo-glyphs, not rendered fonts.
- One Chromium build on one OS; Safari/Firefox decoders (which survivors may use) are not covered.
- CMYK with an ICC profile was tested with one synthetic profile (sharp's built-in); real Adobe-inverted or press profiles are untested and may differ.
- Inputs above 25 MP are rejected by `prepareForPdq` (covered by unit test, not by this report); the crawler cannot fingerprint those.
- This measures decode agreement only, not match recall against a real hash database.
